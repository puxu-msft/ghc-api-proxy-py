# 客户端块级交付

对非流式请求而言，实质上做到了比“块级交付”更粗粒度的“一次性交付”，天然满足块级交付承诺。本文主要关注流式请求。

对于流式请求而言，传统的 SSE 流式响应是按事件交付字符串流的，当出现中断，会将不完整的内容发给客户端，我们决定放弃该特性，强制代理端在缓存中积累完整块后才交付给客户端。一个完整块的定义是一个 `_start` 事件和一个 `_end` 事件之间的所有内容。每次形成一个完整块就交付并从缓存中移除。

## 客户端响应头

不等到出现完整块才转发上游响应头给客户端，但也不可能每次上游尝试都能提交响应头给客户端，而是只在第一次 HTTP 200 尝试时转发响应头给客户端。后续重试若 HTTP 报错只能转化为 SSE error。例如，后续上游尝试发送 HTTP 429，但我们找不到合适的载体转发 `Retry-After`。接受这个限制，只用 SSE error 告知出现限流。

## 客户端保活与超时

当客户端响应头提交后，按配置 `client_delivery.sse_ping_interval` 的时间间隔发送 SSE ping。

配置有两个最大时长保底：
- 一次上游请求的最大时长（`upstream_request_retry.upstream_request_deadline`）；
- 一次客户端请求的最大时长（`client_delivery.client_request_deadline`）。

当客户端请求超时，如果已发 HTTP 200 响应头，则放弃当前缓冲块，发 SSE error 再收尾；如果还没发 HTTP 200 响应头，则直接返回 HTTP 504 Gateway Timeout。

当客户端请求被杀死（被取消或超时），应该取消上游请求，避免无谓的资源消耗。
