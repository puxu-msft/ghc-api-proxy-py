# TypeScript 参考实现：Responses／Anthropic converters 与 reasoning／tool stream handling

## Verdict

三个快照都能提供可移植机制，但架构不同：两个 Copilot Chat 仓库不是 Responses↔Anthropic 的直接互转器，而是分别把两种协议适配到统一的 `Raw.ChatMessage`／`IResponseDelta`；`caozhiyuan-copilot-api` 才是 Anthropic client→Responses upstream→Anthropic response 的显式 bridge。最值得移植的是“内部规范模型 + 按 `output_index`／block index 管理的流状态机 + opaque reasoning round-trip + terminal-event 校验”；不可照搬的是将 reasoning／compaction 元数据拼进 Anthropic `signature` 的私有编码，以及用占位 thinking 文本兼容特定客户端。

12. **`caozhiyuan` reasoning／compaction carrier。** `/home/xp/src/refs/caozhiyuan-copilot-api/src/routes/messages/responses-translation.ts:352` 将 Anthropic signature 解为 Responses `encrypted_content + id`，`:383` 用最后一个 `@` 分隔；反向在 `:508` 附近把它重新拼成 `encrypted_content@id`。compaction 则用 `cm1#<encrypted>@<id>` 私有前缀。它能借 Anthropic signature 穿越不认识 Responses opaque item 的客户端，但限制明确：这是私有、未版本化的字符串协议，空 ID 会被保留为 `id: ""`，delimiter／来源域校验弱于 upstream 的 `rs` gate，不应原样成为跨实现公共契约。

14. **终止、故障与适用边界。** `/home/xp/src/refs/caozhiyuan-copilot-api/src/routes/messages/responses-stream-translation.ts:460` 在 completed／incomplete 时先关闭所有 block，再发 `message_delta + message_stop`；`/home/xp/src/refs/caozhiyuan-copilot-api/src/routes/messages/api-flows.ts:197` 检测 transport 结束但没有 terminal event 并补发 error。`:35` 起的连续空白 guard 可阻止异常 tool arguments 无限换行，但固定阈值属于策略，不是协议规则。另一个限制是该 translator 对未知 event 默认返回空数组；移植时应增加可观测计数／日志，并用真实 SSE 序列测试交错 text、reasoning、多 tool、缺 added、仅 done、incomplete、failed 与 transport EOF。本报告是锚定上述 HEAD 的静态只读调查，未对远端服务做 live-wire replay。
