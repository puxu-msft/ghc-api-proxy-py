# Anthropic Messages request → OpenAI Responses request converter 调查

## 评审摘要

**评审范围**：只读审阅 `/home/xp/src/copilot-api-js` 固定最新 HEAD `8d5c861c2e079b92401dd8ccd49695a363d078fe` 中 Anthropic Messages request → OpenAI Responses request 的 direct converter、生产调用链及测试。关键工作树文件的 blob 已逐一与该 HEAD 的实现基线对账；HEAD 最后一次前进仅修改 history 文档，相关实现与测试路径零改动。

**总体 verdict**：**修复 major 后可进入**。核心字段映射完整且大多有单元测试，但生产链存在工具名 sanitization 未接入的问题，content block 聚合还会改变同一 turn 内的相对顺序。

**blocker 数**：0。

**双视角覆盖证据**：机械核对覆盖 converter 白名单组装、system helper、content block 分支、tools/tool_choice、reasoning capability gate、metadata last-mile、CellAssembly/driver 调用链和测试断言；第一人称执行模拟了 string/array system、user/assistant 混合 block、普通与 server tools、forced choice、echoed reasoning、未知字段、stream true/false、模型重映射，以及非法工具名进入真实 S2→S3→S4 链路。用户裁决 **buffering 不变**：本报告不建议修改 buffering，也未调查或改动 response buffering 实现。

## 事实性发现

1. **[major] 工具名 sanitizer 未接入 Anthropic→Responses 生产链**。Anthropic parse 只构建 mapper 并存入 context（`/home/xp/src/copilot-api-js/src/lib/codec/anthropic/codec.ts:389`、`:432-446`）；driver 随后先做 S2 translate，再做 S3 rewrite（`/home/xp/src/copilot-api-js/src/lib/pipeline/driver.ts:328`、`:368-371`）。Responses cell 的 S2 调 direct converter，但 S3 明确返回空 rewrite（`/home/xp/src/copilot-api-js/src/lib/codec/openai-responses/openai-responses-cell.ts:88-107`），S4 仅调用 `prepareResponsesRequest`（同文件 `:109-113`；`/home/xp/src/copilot-api-js/src/lib/codec/openai-responses/openai-responses-leg.ts:110-118`），而后者只 clamp `user` 并清理非法 `function_call.id`（`/home/xp/src/copilot-api-js/src/lib/openai/request-preparation.ts:62-69`、`:106-109`）。因此开启 `sanitizeToolNames` 时，converter 产出的 tool declaration、历史 `function_call.name` 和 forced `tool_choice.name` 仍是原名；`applyResponsesToolNameSanitization` 虽已能同步三者（`/home/xp/src/copilot-api-js/src/lib/openai/tool-name-sanitize.ts:183-224`），该链路却没有调用它。失败场景是目标模型禁止 `mcp.tool` 这类名称时，wire 仍携带点号并被 upstream 拒绝。建议在 S2 后、S4 前建立并应用一个共享 mapper，且确保 response restore 继续读取同一 mapper；不要只在 converter 内单改 `tool_choice`。

2. **[major] content block 的相对顺序会被聚合改变**。assistant 分支先按扫描顺序 push `tool_use`，循环结束后却用 `unshift` 把所有文本合并项放到所有 tool calls 前，再把 reasoning 全部放到最前（`/home/xp/src/copilot-api-js/src/lib/openai/translate/anthropic-to-responses-request.ts:214-255`）；因此 `[tool_use, text]` 变成 `[message(text), function_call]`，与该文件 `:201-207` 的“block order preserved”描述不符。user 分支扫描时 push `tool_result`，最后才 append 聚合后的 text/image message（同文件 `:278-306`），所以 `[text, tool_result]` 也被反转。现有测试只覆盖 text 在 tool_use 前的顺序（`/home/xp/src/copilot-api-js/tests/openai/anthropic-to-responses-request.unit.test.ts:339-364`），无法抓到反例。建议按连续 block/run 产生 items，或冻结并明确记录这种重排是协议要求；无论哪种决策，都补反向排列与交错排列测试。

3. **[行为] `system` 映射为 `instructions`**。converter 在 `/home/xp/src/copilot-api-js/src/lib/openai/translate/anthropic-to-responses-request.ts:113-116` 调用共享 helper；string 原样返回，`TextBlockParam[]` 以 `map(...).join("")` 无分隔拼接，并丢弃 block-level `cache_control`（`/home/xp/src/copilot-api-js/src/lib/openai/translate/anthropic-to-cc-request.ts:137-147`）。空结果不发 `instructions`（converter `:156-160`）。现有 envelope 测试只覆盖 string system（`/home/xp/src/copilot-api-js/tests/openai/anthropic-to-responses-request.unit.test.ts:472-494`），没有 array system 的 direct-bridge 专属断言。

4. **[行为] messages/content blocks 为显式分类转换**。非空 string content 变成一个 Responses message item，空 string 整项省略（`/home/xp/src/copilot-api-js/src/lib/openai/translate/anthropic-to-responses-request.ts:187-198`）。user text/image 聚合为 `input_text`/`input_image`；base64 image 变 data URL，URL source 原样透传（同文件 `:278-306`、`:351-355`）。assistant text 聚合为一个 `output_text` message，`tool_use` 变 `function_call`，只携带 `call_id/name/JSON.stringify(arguments)`，不伪造 `id`（同文件 `:214-255`、`:309-320`）。`tool_result` 变 `function_call_output`；array content 只拼 text，image 丢弃并告警，`is_error` 加 `[tool_error] ` 前缀（同文件 `:323-348`）。这些主路径由 `/home/xp/src/copilot-api-js/tests/openai/anthropic-to-responses-request.unit.test.ts:323-426` 覆盖。

5. **[行为] tools/tool_choice 是白名单映射**。普通 Anthropic tool 变 Responses function tool，`description` 与 `input_schema→parameters` 条件保留；`cache_control`、`defer_loading`、`eager_input_streaming` 等未列字段不透传（`/home/xp/src/copilot-api-js/src/lib/openai/translate/anthropic-to-responses-request.ts:400-437`）。server tool 目前只有 `web_search_*→{type:"web_search"}`；`web_fetch`、`code_execution` 和 client-executed builtin 没有表项，会 strip+warn（同文件 `:362-395`）。choice 映射为 `auto→"auto"`、`any→"required"`（但全部 tools 被剥离时省略）、`none→"none"`、named tool→对应 function 或 builtin choice；声明不存在或已剥离时省略 choice（同文件 `:439-479`）。测试覆盖见 `/home/xp/src/copilot-api-js/tests/openai/anthropic-to-responses-request.unit.test.ts:221-321`、`:428-440`。

6. **[行为] thinking 同时影响 request-level reasoning 配置与历史 reasoning item**。顶层 `thinking.enabled.budget_tokens` 经共享 heuristic 变 `reasoning.effort`，`adaptive` 读取 `output_config.effort` 并 clamp，均附 `summary:"auto"`；disabled/absent/无有效 effort 时省略，传入 resolved model 时还要求其 `reasoning_effort` capability 非空（`/home/xp/src/copilot-api-js/src/lib/openai/translate/anthropic-to-responses-request.ts:485-506`；capability gate 在 `/home/xp/src/copilot-api-js/src/lib/openai/translate/anthropic-to-cc-request.ts:404-411`）。assistant 历史中的本代理 sentinel-signed thinking 会重建为 `reasoning` input item并恢复 `encrypted_content`；foreign/unsigned thinking 被聚合记录 degradation 后丢弃，`redacted_thinking` 直接丢弃（converter `:127-143`、`:231-275`）。相应测试见 `/home/xp/src/copilot-api-js/tests/openai/anthropic-to-responses-request.unit.test.ts:43-219`、`:442-447`。

7. **[行为] metadata 只保留 `metadata.user_id→user`，且 wire boundary 会再裁剪**。converter 的唯一 metadata 输出位于 `/home/xp/src/copilot-api-js/src/lib/openai/translate/anthropic-to-responses-request.ts:167`；其他 metadata/未知子字段不透传。`prepareResponsesRequest` 在 OpenAI wire boundary 对超长 `user` 优先提取 JSON `session_id`，否则截断到代码声明的 64 字符限制（`/home/xp/src/copilot-api-js/src/lib/openai/request-preparation.ts:43-79`）。这意味着 effectiveRequest 可保留 converter 结果，而 outbound wire 的 `user` 可能更短；核心 converter 测试只覆盖短值（`/home/xp/src/copilot-api-js/tests/openai/anthropic-to-responses-request.unit.test.ts:472-494`）。

8. **[行为] `max_tokens`、`stream`、unknown fields 与 model 的边界明确**。converter 无条件写 `max_output_tokens: payload.max_tokens`，显式提供 `stream` 时原值复制；S4 的 `PreparedRequest.stream` 用 `wire.stream ?? false`，不会改变 payload 内显式 false（`/home/xp/src/copilot-api-js/src/lib/openai/translate/anthropic-to-responses-request.ts:156-168`；`/home/xp/src/copilot-api-js/src/lib/codec/openai-responses/openai-responses-leg.ts:110-118`）。converter 是从零白名单重建对象，没有 spread source，故 unknown top-level fields 被丢弃；未知 assistant block 落入静默 default，未知 user/server-result block 也静默丢弃（converter `:247-249`、`:297-300`）。已明示丢弃 `top_k`、`stop_sequences`、`cache_control`、`context_management`，`output_config` 除 reasoning effort 外也不保留（converter `:150-155`）。converter 自身复制 `payload.model`（`:157`），但生产 parse 已先把它替换为 resolved model（`/home/xp/src/copilot-api-js/src/lib/codec/anthropic/codec.ts:398-403`），所以实际 wire model 是 resolved name，而不是 client 原始拼写。

9. **[调用链] 生产链为 driver → CellAssembly → hub direct bridge → converter → Responses last-mile**。`createPipelineDriver.runRequest` 在 `/home/xp/src/copilot-api-js/src/lib/pipeline/driver.ts:328-371` 完成 parse/inbound/route 后调用 cell `translateOut`；`/home/xp/src/copilot-api-js/src/lib/codec/openai-responses/openai-responses-cell.ts:88-103` 调 `translateRequestVia`；hub 在 `/home/xp/src/copilot-api-js/src/lib/pipeline/hub-translate.ts:148-154` 构造 direct bridge，并在 `:172-202` 的二维表中分派 Anthropic+Responses/WS Responses；converter 产出 logical Responses body；cell 的 S3 为空，再由 `/home/xp/src/copilot-api-js/src/lib/codec/openai-responses/openai-responses-leg.ts:110-118` 和 `/home/xp/src/copilot-api-js/src/lib/openai/request-preparation.ts:106-123` 生成最终 wire 与 headers。该链跳过 CC intermediate；hub shape 测试在 `/home/xp/src/copilot-api-js/tests/pipeline/hub-translate.unit.test.ts:62-73` 明确断言 `input` 存在而 `messages` 不存在。

10. **[minor] 测试覆盖存在两个可信度缺口，本次执行也不能记为 green**。核心 converter suite 覆盖 reasoning、server tools、content、choice 和 envelope（`/home/xp/src/copilot-api-js/tests/openai/anthropic-to-responses-request.unit.test.ts:43-494`）；pipeline integration 只断言 outbound 是 array-shaped `input`，且标题/注释仍称“四跳 Anthropic→CC→Responses”，与当前 direct bridge 不一致（`/home/xp/src/copilot-api-js/tests/anthropic/anthropic-nonstream-roundtrip.it.test.ts:167-203`）。最新 tool-choice sanitizer 测试仅直接调用 helper（`/home/xp/src/copilot-api-js/tests/openai/tool-name-sanitize.unit.test.ts:158-184`），没有 Anthropic→Responses 生产链集成用例。调查期间两次运行相关 Bun tests 均在开始执行 converter suite 后收到共享终端的外部 `Ctrl-C`，因此本报告只确认测试源码覆盖，**不声称本次测试通过**。建议新增真实 driver inspection/transport capture 用例，断言非法 tool name、历史 function_call 与 forced choice 在最终 Responses wire 上一致，同时修正过时“四跳”描述。
