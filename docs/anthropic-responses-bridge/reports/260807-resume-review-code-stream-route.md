## 事实性发现

[major] `src/app/routes/anthropic.py:145-158` — 首 block 前的 delayed-start 阶段不监听 ASGI disconnect，客户端断开后 upstream 可继续无限生成 — route 在返回 `StreamingResponse` 前同步等待 `anext(stream)`；Starlette 的 disconnect listener 只有拿到 response 后才运行。新增 smoke 虽构造了 `disconnect = asyncio.Event()`，但从未 `set()`，因此没有验证 cancel。失败场景是 upstream 在 authoritative done 前停住、客户端先断开：handler仍等待 upstream，不能传播 cancel、关闭 response 或 finalize aborted — 把 delayed-start owner 下沉到可同时 race `receive()` 与 upstream 首批的 ASGI response，或在预取阶段显式监听 disconnect；增加首 block 前与首 block 后真实 disconnect 两个 route-level case，并断言 upstream close、零 retry、一次 failed／aborted finalize和无 orphan task。

[major] `src/app/delivery/responses_anthropic_stream.py:29-46`、`src/app/delivery/anthropic_sse.py:593-605` — `DeliveryFrontier` 把写入 request-local list 当成下游 accepted，未接到真实 ASGI sink outcome — `_BufferedWriter.write()` 只执行 `pending.append(batch)`，随后 `DeliverySession` 立即 `accept_block()`／`accept_terminal()`；route 之后才从 list yield，实际 `http.response.start`／body send 可能尚未发生或失败。因此“accepted”可在零下游 bytes 时成立，也不存在 headers state、partial write或 uncertain state，不能支撑 retry／History 真值 — 让 `DeliverySession` 的唯一 writer 直接拥有 delayed response start 与 ASGI send outcome，或至少由真实 sink 回执后推进 frontier；显式建模 headers、message_start、block、terminal 的 `not_started | accepted | uncertain`，并对 response-start／body 各 byte offset 注入 failure。

[major] `src/app/routes/anthropic.py:41-69,145-158`、`src/app/delivery/responses_anthropic_stream.py:100-119` — post-commit parser／delivery／EOF 错误只让 body iterator 抛异常，不生成 Anthropic `error` SSE — `render_responses_as_anthropic_sse()` 将协议错误归一为 `ApiError`，但 `_history_stream()` 只是记录后重新抛出；route 仅在首批预取时把 `ApiError` 转 HTTP error。首批已发送后同样的错误穿出 `StreamingResponse`，连接突断，客户端看不到规范要求的单一 Anthropic error terminal — 在唯一 sink owner 中根据真实 frontier 分流：precommit 生成 HTTP error，postcommit 串行发送一个 Anthropic `error` batch并关闭，且禁止 `message_stop`；覆盖 `response.failed`、`error`、clean EOF、malformed event与converter failure。

[major] `src/app/delivery/anthropic_sse.py:619-626`、`src/app/delivery/responses_anthropic_stream.py:91-99` — 所有 `response.incomplete` 都被当成失败，合法 token-limit terminal 无法映射为 `stop_reason="max_tokens"` — parser把 incomplete作为独立 terminal kind，route只有 `completed` 才解析 usage，`DeliverySession._finish_from_terminal()` 对任何非completed直接抛错。Spec冻结了 output-token limit incomplete为合法 Anthropic成功终态 — 在 terminal normalizer 中解析 incomplete reason，允许已知 output-token limit在无open block时带权威usage生成唯一 `message_delta(stop_reason=max_tokens)`＋`message_stop`；content-filter、cancelled与unknown reason继续显式失败，并加入与non-stream usage parity测试。

[major] `src/app/streaming/openai_sse.py:7-19` — SSE parser 对合法 raw framing 不稳健，任意 chunking 下的合同不成立 — 每个 chunk先独立把 `\r`替换为`\n`；若 CRLF 恰跨 chunk，前一块末尾 `\r`与后一块开头`\n`会变成两个换行，可能提前截断 frame。它还只接受`data: `，忽略合法的`data:`无空格形式，且没有按 SSE 字段语义处理 optional single space — 在累计 buffer 上识别完整 line ending，再按 SSE grammar解析字段；覆盖 CRLF 的每个切分点、multi-line data、`data:`／`data: `、空 frame、fragmented `[DONE]`与无terminal EOF，并做随机 rechunk。

[major] `src/app/openai/responses_stream_parser.py:166-172,262-307` — message content lifecycle可被静默丢弃并仍成功 terminal — `response.content_part.added/done`被无条件忽略，message `output_item.done`只标记 item closed而不核对 `item.content` 与已完成 text drafts。只发送 item added＋item done，其中 done含 output_text或未知content part，再发送 completed，会关闭 source但产生零block，随后被渲染为合法零content成功；这违反 strict unknown与no-loss — 对 content-part added/done 建立并验证 typed draft，或在 item done用authoritative content补足／核对每个part；任何未映射part或缺少必需done必须显式失败。增加“done body有content但无对应delta/done”与unknown part的正反控制。

[major] `src/app/openai/responses_stream_parser.py:349-362,491-503`、`src/app/delivery/anthropic_sse.py:424-447` — function arguments只校验delta字符串一致，不在完成时校验JSON object；错误延迟到renderer并逃出统一错误映射 — parser可产出含malformed或非object arguments的`CompletedBlock`；renderer中的 `orjson.loads()`／object check抛出 `JSONDecodeError`或`ValueError`，而 stream adapter只捕获`ResponsesStreamProtocolError`与`ResponsesDeliveryError`。Precommit会越过route的`except ApiError`成为内部异常，postcommit则突断连接；两者都不形成稳定Anthropic错误与正确History cause — 在 parser／semantic conversion完成点严格解析为JSON object并抛具名 protocol/conversion error，renderer只消费已验证immutable值；同时保留统一异常兜底与cause，测试 malformed JSON、JSON scalar／array及postcommit场景。

[major] `src/app/routes/anthropic.py:38-69`、`src/app/history/consumer.py:17-27` — 流式成功History永远以 `response=None` finalize，无法保存 committed Anthropic response／block投影 — `_history_stream()`只用 `AnthropicSSEUsageTap`提取usage，随后调用`history.finalized(context)`而不传response；`HistoryConsumer`直接把该参数赋给`entry.response`。因此 happy-path smoke只证明同一个context与一次finalize，没有断言History响应内容；生产History会把成功流记为completed但无客户端可见response，postcommit partial也没有committed-prefix投影 — 在 cleanup前从 delivery committed-block ledger形成immutable normalized Anthropic projection并传给History；success必须含完整blocks／usage，partial/cancel保留已提交前缀和明确终止原因，且不得从raw SSE在cleanup后重推导。测试应断言实际History entry而非只比较context对象身份。

## 测试可信度结论

新增 smoke 对两件事有真实价值：它通过直接 ASGI `send` 观察证明 authoritative first block完成前 `sent == []`，并证明首个完整batch后才出现 `http.response.start`与Anthropic SSE；它也验证同一个 `RequestContext`对象进入 History／approval／hooks，且旧fail-closed不再阻断route。但它没有执行声明过的disconnect，也没有覆盖任何postcommit失败、incomplete、EOF、usage parity、cancel cleanup、History response或真实sink outcome；没有独立strict Anthropic grammar consumer，也没有正向变异控制。因此当前绿灯即使可运行，也只能放行happy-path接线，不能放行STREAM-MERGE-03～10，更不能据此squash。

## 结论

当前分支已完成真实route、Responses stream请求、parser、block-level Anthropic SSE happy path和同一context的纵向接线；首block前headers/body withholding在该happy path上是真实ASGI行为，旧双层fail-closed也已完整移除。但 lifecycle、delivery truth、error terminal、incomplete、parser framing／no-loss、cancel与History仍有8条major。**不可squash；修复上述major并补route-level正反控制后再复评。**
