OpenAI Responses 能力与翻译路径差距报告

主题：anthropic-responses-bridge； 日期：2026-09-14； 参考项目：gim-home-ghc-tunnel； 范围：OpenAI Responses 与 Anthropic Messages → Responses； 明确排除：OpenAI Chat Completions。

一、结论摘要

我们当前实现的主要路径已经比 gim 更重视 reasoning carrier、能力拒绝、 block-level buffering 和 Responses lifecycle；不应为了追随 gim 而退回到更宽松的 “未知内容直接丢弃或转文本”策略。

gim 最值得借鉴的是一份较清晰的 Responses 能力清单：路由与模型能力判定、 service_tier、compaction、图片和工具字段、web search/citation、 terminal 事件、错误映射以及真实 SSE 形状。我们的主要差距集中在负向行为、 malformed 输入的终态、usage 语义和真实上游事件证据，而不是基础 happy path。

二、范围与参考依据

本报告只比较以下路径：

  • OpenAI Responses HTTP 路由、请求/响应处理和流式事件。
  • Anthropic Messages → OpenAI Responses → Anthropic Messages 翻译。
  • 模型 endpoint/capability 判定、工具、图片、reasoning、web search、usage 和错误终态。

不分析、不移植 gim 的 Chat Completions 支持。当前 gim 参考版本为本地工作树 HEAD 5ac6b721d10cbcd937acf4120e872405282b4b34。

三、能力对比矩阵

领域 gim 的实现特征 我们的实现状态 结论
Responses 路由 支持 /responses 和 /v1/responses； 按模型目录中的 supported_endpoints 选择。 有统一 pipeline routing，并对未知 capability fail-closed； 还区分直通、翻译和不同 driver。 我们的 admission 方向更严格，继续保留。
请求透传 大部分 Responses JSON 透传；强制 service_tier: null， 处理 apply_patch、image generation 和 compaction。 已有字段投影、extensions 和格式 driver，但仍需明确哪些字段是同格式透传、 哪些字段可跨 Anthropic 翻译。 借鉴 gim 的清单，不复制其宽松边界。
Reasoning Responses 输出中的 reasoning item 不转换为 Anthropic thinking； 主要保留文本和工具调用。 有 reasoning proxy carrier，可承载 signature、redacted thinking、 summary 和 encrypted state。 我们的设计更完整，属于核心差异，不能退化。
流式生命周期 处理 output item、文本 delta、工具参数、search、citation 和 terminal 事件。 有较完整的 output-index 状态机和 block-level delivery，但部分 malformed lifecycle 仍可能被降级为成功或静默丢弃。 优先补负向状态机测试和严格终态。
工具与图片 支持 function tool、tool result、URL/base64 图片；不支持项多数直接报错。 function tool 和图片主路径已有；非文本 tool result、vision admission、 图片限制和输出图片仍需明确。 补齐 admission 和 loss 语义。
Web search Anthropic hosted search 映射为 Responses hosted search，保留 source URL、 citation 和可见搜索历史。 已有 hosted/client search 相关路径，但 domain restriction、max uses、 call ID、加密内容和 fallback 语义需要继续收紧。 以安全保真为准，默认不能扩大搜索范围。
Usage Responses → Anthropic 会扣除 cached tokens，并映射 output/reasoning/cache 细节。 已有 usage 转换和上游 usage 保留，但 absent、zero、malformed 的语义尚未完全统一。 区分缺失与非法，保持流式/非流式一致。

四、已确认的主要差距

P0：malformed Responses lifecycle 可能伪装成成功

当前某些非流式或流式异常形状可能被转换为空输出或正常 end_turn。需要拒绝或形成明确 conversion error/fact 的情况包括：

  • 缺失或非法的 terminal/status。
  • 非数组的 output。
  • 重复 output_item.added 或重复 done。
  • 未知 output index、done 无 draft、done 后继续 delta。
  • terminal 事件缺失或多个 terminal 互相冲突。

我们的 Spec 已经要求严格 lifecycle；实现应补齐统一 validator，而不是修改 Spec 去适应宽松行为。

P0：refusal 未形成完整的跨格式语义

Responses refusal content part 必须作为独立语义处理，不能落入 unknown/opaque 后被静默丢弃。非流式和流式都需要一致地产生可观察的 Anthropic 文本/拒绝结果， 并正确设置 stop reason 和 degradation fact。

P1：usage 缺失与 malformed 尚未严格区分

缺少 usage 可以采用明确的 estimated/zero 语义；usage 字段存在但类型错误、 负数、非有限数或结构不一致时，应产生明确的 invalid usage/conversion error， 不能简单吞掉并返回空 usage。

P1：reasoning item 截断判定未完全闭合

reasoning item 需要等待 summary parts、encrypted content、item identity 和 authoritative item done 全部闭合。尤其需要覆盖“前面已有完整 block， 最后一个 reasoning item 被截断”的流式和非流式场景。

P1：opaque 与 malformed 的边界需要收紧

真正未知但结构自洽的字段可以进入 opaque/extension；已知字段的错误类型、 lifecycle 错误、terminal 错误和协议不变量破坏不能全部伪装成未来扩展。

P1：图片、工具结果和 web search 的 loss 需要显式化

  • 在翻译前根据模型 vision capability 做 admission。
  • 明确 tool result 中图片或结构化 block 的保留、降级或拒绝策略。
  • web search 的 domain restriction 默认不能静默丢弃而扩大搜索范围。
  • 明确 citation、加密网页内容、search call ID 和 max uses 的 loss。
  • stop reason 不可逆时记录可审计 loss，而不是静默改写。

P2：Responses 专属能力需要明确不做项

对以下能力应在能力矩阵中明确为“同格式可能透传、跨 Anthropic 翻译暂不支持” 或“明确拒绝”，而不是让它们依赖未知 item 的偶然处理：

  • background/asynchronous response。
  • previous response/conversation server-side state。
  • audio input/output。
  • annotations/citations 的完整跨格式转换。
  • image output、MCP、custom、file search、computer-use 等 server tools。
  • Responses WebSocket transport。

五、改进后的实施方案

P0：先修正可观察正确性

  1. 建立流式与非流式共享的 Responses lifecycle validator。
  2. 为 refusal 建立 typed semantic block 和双向转换。
  3. 区分 absent usage、zero usage 和 malformed usage。
  4. 完成 reasoning item 的 authoritative close/incomplete 判定。
  5. 保证错误不会伪装成成功的空消息或 end_turn。

每项都需要 paired non-stream/stream negative-control 测试，并保持现有 block-level buffering 和 reasoning carrier。

P1：补齐跨格式语义和 admission

  1. 补充图片 source、MIME、大小、数量和模型 vision capability 校验。
  2. 为非文本 tool result 定义稳定的 Responses 表达或明确拒绝。
  3. 收紧 web search domain restriction、citation 和 loss 记录。
  4. 统一 stop reason 的可逆映射和不可逆 loss 观测。
  5. 建立已知字段、未知扩展和 malformed source 的分类表。

P2：完成能力边界和证据矩阵

  1. 更新 Responses compatibility matrix，列出支持、降级、拒绝和同格式透传范围。
  2. 增加真实 upstream cassette：
  • 真实 function call stream。
  • response.failed、response.cancelled 和 error event。
  • refusal content part。
  • 图片请求和 vision admission。
  • reasoning summary 截断。
  • web search citation 和 domain restriction。
  1. 对同一异常输入验证流式与非流式的终态、usage、history 和错误投影一致。
  2. 明确暂不实现 Responses WebSocket，而不是保留模糊的半支持状态。

六、明确排除项

  • 本报告不评估 gim 的 OpenAI Chat Completions 实现。
  • 当前方案不复制 gim 的 Chat fallback 行为。
  • 不会为了扩大表面兼容性而放宽当前 Spec 对 lifecycle、reasoning carrier 和 block-level delivery 的约束。
  • 不会把 Responses 全量 API 支持误称为 Anthropic Messages 跨格式已支持。
