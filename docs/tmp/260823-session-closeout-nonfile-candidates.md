### 1. 可达性判据一天之内被四个盲区各击穿一次 —— 两位评审共同判为最重

**同源的第五件事**：归档之后 `tests/unit/test_module_boundaries.py` 原本那条「新链不得 import 旧链」**变成恒真断言**——旧链的名字已不在 `src/` 里，断言从此什么都不证明，而它照样是绿的。已改为「这些名字解析不到」。**一条断言的意义会被它所守护的代码的移动悄悄抽空，而测试全绿正是这件事发生时的表现。** 落点同上。

### 2. 带装饰的输出喂给下一条命令，装饰进了比较的那一侧 —— 三实例同日同形态

- `rg -o` 把 ANSI 转义码截进文件名 → `git status -- <不存在的路径>` 全返回空 → 读成「全都干净」；
- `git grep -h -o` 留下行号前缀 → 比对 `1112:.dev/...` → 24 条路径检查**全部 MISSING**。**方向最坏：假阴性伪装成发现**，会派你去修 24 个没坏的地方，而「全都坏了」这种整齐结果看起来像找到了系统性问题；
- `if out.returncode == 0 else []` 把失败静默换成空列表 → 「0 app modules」。**它有一半是对的**（同一次输出里的 `app.core reachable = NO` 在修好后仍为真），部分正确的假结果比全错的更难识破。

**落点**：记忆 [[prove-the-probe-ran-before-reading-its-number]] 新增「相邻的一族」整节，含 `rc==0` 本身也可能是假的（2026-08-23 实测 `uv run` 在 `ModuleNotFoundError` 下 `${PIPESTATUS[0]}` 仍为 0）。

### 3. 护栏行为边界与「拦的是整次调用」

六次往返换来的运行时知识，原本完全无载体。最贵的一条：**护栏是 PreToolUse，拦下时同一次 Bash 调用里的其他命令一起没跑**——heredoc 写的提交信息文件根本不存在，症状要到下一步 `git commit -F` 才出现，看起来像「写文件失败」而不像「整次调用被取消」。

**落点**：新记忆 [[bash-guards-block-the-whole-call-not-the-command]]，含删除护栏三个硬要求、`GIT_DISCIPLINE_OK=1`、有意不走 `allow_unenumerated_targets` 旁路的判断、以及两处它管不到／管错的地方。

### 4. 引 2026-08-19 授权时截断掉一个豁免项与一个前置条件

授权原文有**两个**豁免项（`spec.md` 的可观察行为合同、`docs/.human-controlled/`），只引了后一个；「可局部调整」那节的前置条件「只要不破坏上述五项核心与 Spec 行为」也丢了——**等于删掉一道门**。**失效方向永远是放宽而不是收紧**：转述权威文本时的静默截断，把「需要裁决」变成「已获授权」。

### 5. 同一搜索盲区在两天内击发三次，三次都靠别人换搜法才发现
