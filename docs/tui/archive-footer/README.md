# 档案：实时 footer

底部那一行「当前有哪些请求在飞」的面板。2026-08-19 至 08-20 完成。

行为契约见 `../spec.md`；本文件记录**怎么定下来的**和**踩过什么**。

## 一、机制选型：为什么是 `rich.Live`

项目已记录的选型是 `textual`（`docs/2604-rewrite/lib-survey/SELECTIONS.md`）。**没有采用**，因为它产生不出要的形态：textual 的 App 要么接管备用屏（日志不再进原生 scrollback，翻不回去），要么以 inline 模式渲染固定块。要的是「日志按原生终端滚动 + 其下一行浮动面板」。

改用 `rich.Live`。`rich` 是 `textual` 自己的渲染内核，所以这是在同一套已选栈内挑层级，不是引入新技术栈；被放弃的只是「跑全屏 App」这一形态。**这仍然是对已记录选型的偏离。**

对照过的第三条路是 **DECSTBM 滚动区**（`\x1b[<top>;<bottom>r`），也就是 `copilot-api-js` 用的机制。没有采用，但保留为对照臂：它需要自己管理光标停泊与滚动区恢复，一旦异常退出就把终端留在残缺状态。

选型依据是实测而非文档，见 `.dev/exp/tui-footer/` 下的三个 driver（`driver_rich_live.py`、`driver_decstbm.py`、`driver_naive.py`）与当时的结论。四类压力下 `rich.Live` 均干净：稀疏日志 + 高频重绘、超宽折行、窄终端、快速连续输出。

## 二、由环境探测决定，没有配置开关

裁决于 2026-08-19。一个开关无从知道进程是被 systemd 拉起、被重定向进文件、还是跑在设了 `TERM=dumb` 的 CI 里，而这三种情形的正确答案各不相同；直接问环境在三种情形下都对，且不需要任何人维护一个设置。

**探测出三项彼此独立的能力，而不是一个布尔**——这一点是有意的，也是最容易被合并掉的设计：

- `live`（能否开实时区域）：stderr 是 TTY，且 `TERM` 既非空也非 `dumb`，且未设 `CI`
- `color`：`live` 成立且未设 `NO_COLOR`
- `unicode`：目标流的**编码**能否承载该字形

合并成一个布尔会把「字节数用 `↓` 还是 `<`」绑到「能不能移动光标」上，而这是两个无关的问题：管到 `tee` 的管道能好好承载 UTF-8，却绝不能收到移动光标的转义；`TERM=dumb` 的终端仍然是终端，只是只收纯文本行。

`unicode` 用**编码**判断而不是按 `TERM` 或平台猜，因为后者在旧代码页上两个方向都会猜错。还要看 `errors`：一个会替换不可编码字符的流不会抛异常，字形会静默变成 `?`。

## 三、宽度纪律：footer 永不超过一物理行

这是硬不变量，不是优化项。实测未截断时在 40 列下每次都失败：footer 折成第二行，其中 DECSTBM 那条路的溢出行还会跑到保留区之外污染屏幕。

实现是单一出口：剥除全部 C0 控制字符（任何一个都会强制第二物理行），再截断到 `columns - 1` **显示列**（-1 用于避开某些终端的末列自动换行）。

显示预算分两轮发放：先决定**哪些模型出现**（每个按最小形态度量，装不下的收进 ` | +K more` 尾巴），再把剩余列**轮转**发给已显示的模型，一次加一个请求。这样一个繁忙模型无法饿死其它模型；宽终端显示全部在飞请求，窄终端退化为每模型最慢的几个，而不是整组消失。

### 踩过的坑：code point 不是显示宽度

评审发现（`reports/260819-review-request-log-footer-merged.md`，major）：`model="界" * 36, columns=80` 时 `build_footer` 产生 48 个 code point 但 **84 个显示单元**，实测在生产同款 Rich 接线下换行，突破了上面那条硬不变量。`no_wrap=True` 救不了——84 cells 塞不进 79 cells 的预算。

修法是全程按**终端单元**计量（`rich.cells.cell_len` / `set_cell_size`），并在 PTY 测试里加入宽 CJK／emoji 模型名断言无第二行。

另一个相关的坑：`set_cell_size` 会把每一帧都**补齐**到目标宽度。footer 只应在过宽时裁，不应补——否则每帧都拖着一串尾随空格。

## 四、并发安全：刷新线程不是事件循环线程

评审发现（同上，major），也是本块工作里最值得记住的一条。

当时 registry 的注释写着「所有变更都在 event loop 线程，所以不需要锁」。**这个注释是错的，因为读者不是 event loop**：`FooterTui` 以默认 `auto_refresh=True` 构造 `Live`，Rich 的 `Live.start()` 会起一个 `_RefreshThread`，该线程调用 `snapshot()` 遍历 live `dict`；而请求路径在事件循环线程里 add/remove/set。

双线程压力下已实际复现 `RuntimeError: dictionary changed size during iteration`。真实后果不是崩服务，而是**刷新线程异常退出、footer 冻结，并可能把隐藏光标留在终端上**——请求继续被正常服务，只有观察面死了，所以极易被当成「没问题」。

修法：`threading.Lock` 同时保护所有 mutation 与 snapshot 的复制。回归测试必须让渲染线程与 request mutation **真的同时跑**，并先用去掉锁的版本证明它会红。

## 五、生命周期可观测：登记发生在请求到达时，不是 body 读完后

用户报告：请求 drained 之后程序卡住，而 **live footer 是空的**，无法观测在等什么。

一度以为要给读 body 或 drain 加超时。**用户否决了这个方向**，并指出真正的问题：「这是真实的已存在请求，应该正确处理，但 live footer 无任何显示，所以用户无法观测，这才是问题。」

根因是登记时机：登记原本发生在 body 读完之后，于是**一个宣告了 body 却停止发送的客户端在显示上根本不存在**。footer 空白，而 shutdown 在等它——等它是**对的**，半发送的请求是真实请求，所以错的从来不是等待，而是没有任何东西说明在等什么。

修法是把登记提到 `_serve` 入口，读第一个字节之前。这条测试只能在 `body()` 内部断言，因为那是唯一的窗口：`_serve` 返回后再看，registry 已空，有没有修都一样。

### 相关：流式响应的 body 可能根本不运行

评审发现（major）：流式请求把唯一的注销与完成日志交给交付生成器的 `finally`，但客户端在第一块被拉取前消失时，一个**从未被迭代过的 async generator 没有挂起的栈帧**，关闭它什么也不运行。结果是 footer 上留下一条永不消失、时钟一直涨的记录，且永远不写完成行。

修法：覆写 `StreamingResponse.__call__`，把 `finally` 放在框架所做的一切之外——那是唯一能在首次迭代前失败时仍然执行的位置。复现手段是让 `http.response.start` 的 send 失败。

## 六、其它已确定的行为

- **`[DRIN]` 前缀**：不再接受新请求但仍在处理存量时的状态。前缀集合见 SPEC。
- **连接数块**：即使没有任何在飞请求也渲染——池化客户端在请求之间保持连接，drain 可能正等着一个请求列表显示不出来的东西。这个组合正是该字段存在的理由。
- **`NO_COLOR` 的判定是「存在且非空」**：`NO_COLOR=` 是某些 shell 中取消继承值的写法，把它读成「禁用颜色」与请求相反。见 https://no-color.org/。
- **英文计数一律用复数**，不为单数分支（`1 clients` 而非 `1 conn`）。用户 2026-08-20 亲自改的，理由是分支拿一点语法体面换来每条报数字的输出多一条代码路径。

## 七、验证手段

PTY + pyte 抓屏，把字节流按终端语义解释成 rows×cols 网格 + scrollback，断言整屏不变量（日志行不被吞、footer 在所有日志行之下且屏上只有一份、scrollback 中没有 footer 副本）。测试在 `tests/tui/`，不进默认扫描。

**这里有一条方法论教训**：第一版判据报「0 吞行」，但拿已知坏实现（naive driver）去跑**也是绿的**——判据没有区分力。先 dump 整屏看见真实的破坏形态，再把判据改成针对机制的断言（footer 行之外出现 `\d+\.\d\ds`），才有意义。`tests/tui/test_footer_screen.py::test_the_scoring_catches_a_footer_that_scrolled_out_of_place` 就是这道正样本对照，它必须一直留着。

另一个失败判据：试图逐行重建期望输出。这对 rich 不成立，因为 rich 按词换行而裸写按列断开。后来放弃了行重建。
