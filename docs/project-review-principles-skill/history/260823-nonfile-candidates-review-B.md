## 3. 对账 A —— 作者列了，而事件源不支持或与事件源不符

### A1 `2.7` 把两次不同机制的失效合并成一条，并误述了第一条的成因 —— **major**

清单写：「探测说『0 个 app 模块』⇒ 搬迁把包搞坏了。不是结果，是 probe 加载了错误的树（`uv run --project <主仓>` 与 `cd src` 两次各一）」。

事件源（`2026-08-22T15:59:17` 的 Bash，工具调用 description 为 `Spot-check the agent's three structural claims`）里，那段探针的实际代码是：

```python
out=subprocess.run([sys.executable,'-c',probe,m],capture_output=True,text=True,cwd='src')
mods=json.loads(out.stdout.strip().splitlines()[-1]) if out.returncode==0 else []
```

输出是 `app.cli: 0 app modules, app.core reachable = NO`。三处对不上：

1. **成因不是「加载了错误的树」，是 `if out.returncode == 0 else []`**——探针用外层 `python3`（系统解释器，没有 `httpx2` 等依赖），子进程 import 直接抛异常、rc≠0，而作者自己写的兜底把失败**静默替换成了空列表**。作者在会话当时说得完全准确：「返回码非零，我却读了空列表当答案」（`15:59:35` 的叙事）。清单把这句最有复用价值的话改写掉了。
2. **「`cd src` 后包根变了」不是机制**。`cwd='src'` 反而让 `import app` 能走通；卡住它的是第三方依赖不在系统解释器里。
3. **「⇒ 搬迁把包搞坏了」这个被推翻的结论在事件源里不存在**。15:59 是布局调查阶段，第 6 步归档要到 18:55 之后才开始。当时那个数字若被采信，得到的错误结论是「`app.cli` 只加载 0 个模块」，而**顺带得到的 `app.core reachable = NO` 在修好探针之后仍然为真**——一个假探针给出了部分正确的答案，这才是这条最值得记的地方，清单也没写。

同一误述已经传染到活文档：`probes/README.md` 写「一次 `uv run --project` 加载了错的树，一次 `cd src` 后包根变了」。**两处都要改。**

（`uv run --project` 那次是真的，发生在 `18:40:46`，与本条无关，应单独成行。）

### 5.2 对 4 处「待确认接收者」+ 1 处「需要接收者」的判断

**`1.1`「热树上用 plumbing 而非 porcelain」—— 值得留，进 `pin-the-commit-you-rewrite-not-head.md`。**
理由：这条与该记忆已承载的 CAS 部分是**同一次操作的两半**——「不碰工作树」决定了改写方法（`commit-tree` 拼链而非重放 patch），「CAS 移 ref」决定了发布方式。拆成两份，读到其中一份的人会以为只需要另一半。反对新建独立记忆：它单独成立时太薄（一句话），而放进去能补上那份现在缺的「怎么造新链」那一段。**建议措辞钉住判据而非结论**：「工作树里有不属于你的改动时，任何会写工作树的 porcelain（`rebase`、`reset`、`checkout`）都出局；剩下的路只有 plumbing 造对象 + CAS 移 ref」。

**`2.6`（ANSI 转义码污染文件名）—— 值得留，但应与 B4 合并，进 `prove-the-probe-ran-before-reading-its-number.md`。**
理由：作者提议的 `the-pattern-is-not-the-predicate` 讲的是「模式排除了该看的行或命中了注释里的名字」，是**模式选错**；而这条与 B4 的形态是**把带装饰的输出直接喂给下一条命令，装饰进了比较的那一侧**，结果是「工作没发生，却产出一个形状正确的空／全 MISSING 结果」——这正是 `prove-the-probe-ran` 那份的主题（它的第 2、3 条就是这个形状）。合并后一条记忆能同时覆盖 `rg -o` 抓 ANSI、`git grep -h -o` 留行号前缀、以及 A1 那个 `rc≠0 → []` 的兜底，**三个实例、同一天、同一形态**，比拆成三处半句强得多。

理由：作者自己判断「它与现有记忆讲的是相反方向的失效」，这个判断成立。但**正因为方向相反，它更该住在同一份里**——那份记忆的主题是「提交范围」，收多了与收少了是同一个决策面的两侧，分开会让人只记住一半（而事实上作者今天两侧各栽一次）。**必须一并写进去的是配套判据**：工作树看不见这种破损，只有**在干净检出里跑 import 冒烟**才看得见；而且 B16 证明**一次 amend 不够，修完要再验一次终态**。

**`4.6`（重指处数）—— 不值得按现状留。**
