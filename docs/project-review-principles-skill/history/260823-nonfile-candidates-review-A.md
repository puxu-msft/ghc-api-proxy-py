# 第 3 节 对作者标「待确认」的 5 处的判断

作者点名要我判的是 1.1、2.6、3.1／5.5、4.6、6.1。

**1.1「热树上用 plumbing 而非 porcelain」——值得留，但不该新开一条记忆。**
我读了 `memory/pin-the-commit-you-rewrite-not-head.md`：第 37 行已经有「`git write-tree` → `commit-tree -p HEAD -F <原信息>` → CAS `update-ref`」这条完整路径，只是它的语境是**事后修一次事故**，不是**主动拆一个提交**。这两者的技术动作完全相同，差别只在触发场景。**建议：在那条记忆里加一句「同一套动作也适用于在热树上主动拆分提交——形态判定见技能 `consolidating-commits-in-a-shared-history`」，不要新建。** 理由：新建一条只有场景不同的记忆，会让下一个人在两条里挑，而它们给的是同一套命令。证据强度：**强**（两份原文都读过）。

**2.6「转义码污染文件名」——值得留，而且应该和 m8 合并成一条。**
作者说 `the-pattern-is-not-the-predicate` 邻近但不覆盖，我同意。但**单独为 ANSI 转义码开一条太窄**。本会话同一个接缝坏了两次、方向相反：`rg -o` 把 ANSI 码带进文件名 → `git status` 查不存在的路径 → **假绿**；`git grep -h -o` 留下 `1112:` 行号前缀 → 路径比对全不匹配 → **假红**。共同的形态是「**把一条 grep 的输出直接当成路径喂给下一条命令**」，而 grep 家族的输出默认带装饰（颜色、行号、文件名），装饰在管道里不消失。**建议：记一条「grep 的输出不是路径」**，正反两个实例都写进去，并写明防法（先剥 `\x1b\[[0-9;]*m`、`--color=never`、`-h` 在 rg 里是 `--help` 而在 git grep 里才是 no-filename）。证据强度：**强**，两个实例都在转录里有命令和输出。

**3.1／5.5「陈旧 pathspec 让 `git add` 整条中止 → HEAD 破损」——最值得留的一条，且必须新建。**
我复核了 `memory/git-commit-takes-the-whole-index.md`：全文没有这个方向（`rg '中止|ops_routes|陈旧'` 零命中），06:26 新补的那一节讲的也是「收多了」。这条讲的是「**收少了，而且静默，而且工作树看不出来**」——`git add` 遇到一个已被重命名的 pathspec 会**中止整条命令**，先前那些参数一个都不进索引，提交照样成功。工作树里一切自洽，`pipeline_app.py` 已经在 import 尚未提交的 `routes/`，**只有另起一棵干净树跑 import 冒烟才看得见**。而且它击发了**两次**：amend 之后 HEAD 里仍是 731 行的旧版 `pipeline_app.py`，第二次才修好。
